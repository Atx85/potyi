Optional language support

Set up a
language server.

Get documentation at the cursor and jump to definitions, using the language tools you choose.

Initial LSP version. This guide covers the development version with LSP support. Older release downloads may not include these commands. Member autocomplete is included; a diagnostic display is not available yet.

Quick start

LSP connects the editor to a separate program that understands your code. It is disabled by default. Use :lsp install <server> for setup on Windows, macOS or Linux.

  1. Install a language server

    Type :lsp install to browse all supported servers. For example, :lsp install unity sets up C#, and :lsp install typescript covers JavaScript, JSX, TypeScript and TSX. Setup reports missing prerequisites for your operating system.

    Installation runs in the background. Escape closes progress; :lsp status shows the latest result and :lsp stop cancels setup. Opening a file never installs software.

  2. Check your setup

    Run :lsp doctor for the current file or :lsp doctor csharp for a specific server. It checks launchers, prerequisites and project requirements. Managed defaults preserve existing configuration.

    For custom settings, :extract-config creates config/lsp.toml beneath Pötyi’s working directory without overwriting existing files.

  3. Enable LSP and configure the server

    Run :lsp start for this window. For automatic LSP in future windows, set enabled = true at the top of config/lsp.toml. The manual recipes below describe project overrides.

  4. Try it in a saved code file

    Place the document cursor on a variable or function name, open the command bar, and run :lsp hover. The server starts in the background. Try :lsp definition to follow a definition, then :lsp back to return.

Choose your language

Keep enabled = true at the top of config/lsp.toml, before any [[servers]] entries. Add the entries for the languages you use. Names must be unique, and the first entry matching a file extension wins. Extensions have no leading dot. Root markers are exact file or directory names, not wildcard patterns.

This guide covers all 18 language families in the bundled syntax configuration, with additional dialect notes. Highlighting and language-server compatibility are separate: rust-analyzer and clangd have been tested with Pötyi; the other recipes follow upstream setup instructions and still need end-to-end verification. Hover, definition navigation, rename, code actions and member autocomplete depend on server support.

Paths, Windows, and checking your setup

Use an absolute executable path when the server is not on Pötyi’s PATH. Installation commands run in your terminal; put only the server executable in command and its individual arguments in args. Pötyi does not expand ~, environment variables, or shell commands in these fields. Replace example absolute paths before use.

On Windows, native servers use their .exe executable. TOML literal strings make paths easy to write, for example command = 'C:\Tools\LLVM\bin\clangd.exe'. For npm-installed servers, do not point to a .cmd or .bat launcher. Set command = "node" (or the absolute node.exe path), then put the server’s JavaScript entry file first in args, followed by its usual arguments.

To find that script, run npm root -g, open the server package’s package.json below that directory, and find the bin entry matching the command name. Resolve that entry relative to the package directory. For example, a Node launch has the shape args = ['C:\absolute\package\server.js', '--stdio']; replace the script path with the actual bin entry. Keep start instead of --stdio for Bash Language Server. A desktop shortcut may inherit a different PATH from your terminal.

After adding a recipe, save the configuration and run :lsp restart. Open a saved file with a matching extension, place the document cursor on a symbol or documented property, and run :lsp hover. Try :lsp definition on a symbol whose source exists locally, then :lsp back. Use :lsp status to check configuration and active sessions. Installing a package alone does not verify that it can analyze your project.

Rust · rust-analyzer

Install a Rust toolchain with rustup, then add the server and standard-library sources. Check the installed server:

rustup component add rust-analyzer rust-src
rust-analyzer --version
[[servers]]
name = "rust"
command = "rust-analyzer"
args = []
extensions = ["rs"]
language_id = "rust"
root_markers = ["Cargo.toml", ".git"]

[servers.initialization_options]
cachePriming = { enable = false }
checkOnSave = false

Open an .rs file inside a Cargo project. This is the server entry included in the extracted defaults; edit that entry instead of adding a duplicate. The example disables cache warming and checks on save to reduce background work.

rust-analyzer installation.

C and C++ · clangd

Install clangd using the upstream instructions: LLVM packages on Windows, Homebrew LLVM on macOS, or your Linux package manager. Use the installed clangd executable path if it is not on PATH. Check:

clangd --version
[[servers]]
name = "clangd-c"
command = "clangd"
args = ["--background-index=false"]
extensions = ["c", "h"]
language_id = "c"
root_markers = ["compile_commands.json", "CMakeLists.txt", ".git"]
[[servers]]
name = "clangd-cpp"
command = "clangd"
args = ["--background-index=false"]
extensions = ["cc", "cpp", "cxx", "c++", "hh", "hpp", "hxx", "h++"]
language_id = "cpp"
root_markers = ["compile_commands.json", "CMakeLists.txt", ".git"]

Provide compile_commands.json with your build flags; CMake projects can generate it with -DCMAKE_EXPORT_COMPILE_COMMANDS=ON. Follow the upstream project setup instructions for locating the database. The examples treat .h as C; move it to the C++ entry for C++ headers. Disabling background indexing reduces background work but can limit navigation across unopened files.

C# · csharp-ls

Install .NET 10 SDK or newer for the current server, then install the global tool. The project itself may target an older framework.

dotnet tool install --global csharp-ls
csharp-ls --version
[[servers]]
name = "csharp"
command = "csharp-ls"
args = []
extensions = ["cs", "csx"]
language_id = "csharp"
root_markers = ["global.json", "Directory.Build.props", ".git"]

Restore the project dependencies with dotnet restore. For a non-Git project, add your exact solution or project filename to root_markers, such as MyApp.sln or MyApp.csproj. With multiple solutions, use args = ["--solution", "/absolute/path/MyApp.sln"]. Standalone .csx scripts depend on the server’s project support. Keep metadata URI mode disabled; Pötyi opens local files only.

Java · Eclipse JDT Language Server

Install Java 21 or newer and Python 3.9 or newer for the launcher. Download and extract a JDT LS milestone distribution from the upstream instructions. Check java -version, then run the extracted bin/jdtls --help launcher. Set JAVA_HOME to the JDK before starting Pötyi.

[[servers]]
name = "java"
command = "/absolute/path/jdtls/bin/jdtls"
args = ["-configuration", "/absolute/path/cache/jdtls/config", "-data", "/absolute/path/cache/jdtls/my-project"]
extensions = ["java"]
language_id = "java"
root_markers = ["pom.xml", "build.gradle", "build.gradle.kts", ".git"]

Replace every absolute path. Use a different -data directory for each Java project; never share it between concurrent sessions. For multiple projects, launch Pötyi from each project with its own config/lsp.toml. On Windows, use command = "python" and put the absolute bin/jdtls script path first in args. Maven/Gradle dependencies must resolve. Definitions inside JARs may use virtual documents that Pötyi cannot open.

Vue: integration status

Pötyi highlights .vue files, but the current Vue language server uses custom tsserver/request and tsserver/response messages to communicate with its TypeScript plugin. Pötyi does not implement that bridge yet, so there is no verified Vue recipe for this client. Do not add .vue to the plain JavaScript entry and expect Vue type information. Ordinary .js, .jsx, .ts, and .tsx files can use the recipes above. See the Vue language server integration instructions.

Member autocomplete

With LSP enabled, type . for member suggestions. Server-advertised : and > triggers also work for ::, -> and Lua/Luau :. Use Up/Down and Enter or Tab, or click a row. Escape closes the popup. Further typing or cursor movement dismisses this initial trigger-only menu.

The same implementation is included on Windows, macOS and Linux, in conventional mode and Vim insert mode. Completion is one undo step; it does not save. Slow or stale replies cannot overwrite newer edits. Suggestions are bounded to 256 items / 512 KiB, with eight visible rows. No autocomplete timers or idle scans are added; language servers have their own resource costs.

Plain text edits and additional imports are supported. Snippets, ongoing word filtering and server commands are not supported. Use :lsp status for the last autocomplete error.

Unity on every platform

Install csharp-ls using the C# recipe, enable LSP, and generate Unity's .sln or .slnx solution and .csproj files if missing in Unity Preferences → External Tools. New extracted defaults include the C# entry; older configurations need it added manually. Open a script under Assets and type transform. inside a MonoBehaviour method.

Pötyi detects the Unity root and selects its named or single root-level .sln or .slnx solution without scanning Library. When both named formats exist, .sln takes precedence. Detection uses the Unity project folder, regardless of where the Pötyi executable is located. Explicit solution arguments take precedence. Windows, macOS and Linux use the same integration. Unity project validation is still pending on all platforms; the shared completion flow has Rust, C++ and mock C# tests.

See the Unity setup and troubleshooting instructions for executable paths, multiple solutions and project generation.

Using the commands

Type :lsp and press Enter or Tab to browse all language-server commands. Select with arrows and Enter or a mouse click. Old command names remain supported aliases.

CommandWhat it does
:lsp actionsChoose a quick fix, including missing imports/includes offered by the server, then review and apply.
:lsp refactorChoose a server refactoring, including extract/move to file when supported.
:lsp rename new_namePreviews a project-wide symbol rename; select Apply changes to commit.
:lsp hoverShows documentation or type information at the document cursor.
:lsp definitionJumps to the first definition returned by the server.
:lsp backReturns to the previous definition-jump location.
:lsp install <server>Installs a supported server using this computer’s platform and preserves project settings.
:lsp doctor [server]Checks launchers, prerequisites and project requirements.
:lsp statusShows configuration and the number of background sessions.
:lsp startEnables LSP for this window and connects for the saved file.
:lsp restartReloads configuration and reconnects after a problem or settings change.
:lsp stopStops sessions and pauses LSP until Start.

The commands work in conventional and Vim modes. Existing shortcuts are unchanged. Hover information appears as plain text in the command bar; use ↑ / ↓ to scroll and Escape to dismiss it. Markdown returned by a server is shown literally.

How it works

Start, status and restart

:lsp start enables LSP for this window without rewriting configuration. It shows connection/loading progress and the result. :lsp restart reloads settings and reconnects. :lsp status shows progress and the last connection or autocomplete result; Enter refreshes it. :lsp stop pauses LSP until Start.

Autocomplete shows “Loading suggestions…” while waiting. Rust-analyzer completion waits for the project-ready notification on the background worker. Other servers may continue indexing after connection. Escape closes the startup panel while startup continues.

A server starts on your first member-access trigger or explicit LSP command. Current unsaved text in matching documents from both panes is synchronized before the request. Later requests use incremental changes when supported, or full-document updates when required. Ordinary typing does not synchronize; member triggers and completion acceptance do.

Preview a rename

Place the cursor on a symbol and run :lsp rename new_name. Click a file or use Up/Down and Enter to inspect replacements, then Enter to return. Select Apply changes to commit; Escape cancels. Normal Undo reverses the rename across files. Keep affected open buffers open while you need this undo history. If an affected file was closed during the rename and you later open it, close it before undoing.

Rename is limited to 64 files, 10,000 edits, 2 MiB per file and 16 MiB total before/after text. Each preview shows up to 40 replacements with long text shortened. Preparation runs in the background; Apply and Undo validate and write the bounded changes on the editor thread. Stale or unsupported edits are rejected. Run :lsp refactor on a declaration or selection to choose an extract/move-to-file action offered by the server. File creation, moves, deletion and annotated workspace edits can be reviewed and undone. Existing destinations and unsupported operations are rejected. See the text guide for undo and recovery details.

Background work, bounded resources

Server startup, communication, and shutdown run on background threads. An explicit request copies at most 2 MiB per document on the editor thread. Language servers may still index dependencies or run build tools according to their own settings, so they add memory and CPU usage while running.

Pötyi allows at most two sessions, one per configured server and project. A detected Unity root takes precedence for C#; otherwise a configured .git marker takes precedence; otherwise the nearest root marker is used, falling back to the file’s directory. A session stops when no matching documents remain open.

Your edits stay protected

Definition jumps reuse open buffers and preserve unsaved text, read-only state, and undo history. A new file uses a clean pane. If both panes have unsaved changes, the jump is refused. Returned locations are checked before replacing a pane.

Results are discarded if either document changes, the requesting cursor moves, the file changes, or the command bar is dismissed or edited. Actions apply only reviewed workspace edits. Open buffers remain unsaved; Apply writes unopened files identified in the preview. Server-requested commands remain disabled.

After editing server settings, run :lsp restart. Start/Stop override enabled for the current window; use the configuration setting to choose the default for future windows.

Troubleshooting

“LSP is disabled” or no matching server

Check that you edited config/lsp.toml under the editor’s working directory and saved it. Put enabled = true before all server entries. Confirm that the document’s extension appears in a server’s extensions list. Run :lsp status to check the selected configuration.

The server cannot start

Run the configured executable from a terminal. If it cannot be found, install it or use an absolute path in command. Apps launched from a desktop shortcut can have a different PATH from your terminal. Verify that the configured arguments start the server in stdio LSP mode.

No hover information or definition

Place the document cursor on a symbol, rather than whitespace, and try again. Confirm that the server supports the requested feature and can load your project’s dependencies and build configuration. Large projects can take time to analyze. Generated or decompiled definitions are not supported in this version.

The server times out or keeps waiting

Initialization has a 30-second limit and feature requests have a 15-second limit. Run :lsp restart to cancel pending work and reconnect. Pötyi attempts a brief shutdown before terminating an unresponsive server.

The command disappears or a jump is refused

Moving the cursor, editing, switching files, or dismissing the command bar can make a pending result outdated. Run the command again at the intended location. If both panes have unsaved edits and a definition needs another file, save one pane first.

The document is not supported

Save the file before requesting LSP help. Open documents must contain valid UTF-8 and be no larger than 2 MiB. Files outside these limits remain editable with Pötyi’s existing features. If the LSP commands themselves are unknown, your editor build predates LSP support.

Current limits

This version provides hover, definition navigation, return navigation, symbol rename, quick fixes, file refactorings and member autocomplete. It does not yet display diagnostics, signature help, references, or semantic highlighting. Dynamic capability registration, project file watchers, and virtual documents are also not implemented.

For implementation details and test coverage, see the text guide. The automated checks cover protocol framing, Unicode, incremental updates, unsaved buffers, navigation safety, timeouts, cancellation, and server crashes.

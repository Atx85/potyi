Initial LSP version. This guide covers the development version with LSP support. Older release downloads may not include these commands. Completion and diagnostics are not available yet.

Quick start

LSP connects the editor to a separate program that understands your code. It is disabled by default. Pötyi does not download or install language servers.

  1. Install a language server

    Choose a server from the language recipes below. Each recipe includes installation steps, settings, and project notes. Install the server itself; an extension for another editor is not enough.

    Check that it runs from a terminal, for example rust-analyzer --version or clangd --version.

  2. Extract your settings

    In Pötyi, press Ctrl + P, enter :extract-config, and press Enter. Existing configuration files are preserved.

    This creates config/lsp.toml beneath Pötyi’s working directory—the folder it was launched from. Configuration is not stored relative to each document.

  3. Enable LSP and configure the server

    Open config/lsp.toml, change the top-level setting to enabled = true, and add an appropriate server entry below. Save the configuration. If a server was already running, use :lsp-stop.

  4. Try it in a saved code file

    Place the document cursor on a variable or function name, open the command bar, and run :hover. The server starts in the background. Try :definition to follow a definition, then :lsp-back to return.

Choose your language

Keep enabled = true at the top of config/lsp.toml, before any [[servers]] entries. Add the entries for the languages you use. Names must be unique, and the first entry matching a file extension wins. Extensions have no leading dot. Root markers are exact file or directory names, not wildcard patterns.

This guide covers all 18 language families in the bundled syntax configuration, with additional dialect notes. Highlighting and language-server compatibility are separate: clangd has been tested with Pötyi; the other recipes follow upstream setup instructions and still need end-to-end verification. Only hover and definition navigation are available in this editor version, even when a server offers more features.

Paths, Windows, and checking your setup

Use an absolute executable path when the server is not on Pötyi’s PATH. Installation commands run in your terminal; put only the server executable in command and its individual arguments in args. Pötyi does not expand ~, environment variables, or shell commands in these fields. Replace example absolute paths before use.

On Windows, native servers use their .exe executable. TOML literal strings make paths easy to write, for example command = 'C:\Tools\LLVM\bin\clangd.exe'. For npm-installed servers, do not point to a .cmd or .bat launcher. Set command = "node" (or the absolute node.exe path), then put the server’s JavaScript entry file first in args, followed by its usual arguments.

To find that script, run npm root -g, open the server package’s package.json below that directory, and find the bin entry matching the command name. Resolve that entry relative to the package directory. For example, a Node launch has the shape args = ['C:\absolute\package\server.js', '--stdio']; replace the script path with the actual bin entry. Keep start instead of --stdio for Bash Language Server. A desktop shortcut may inherit a different PATH from your terminal.

After adding a recipe, save the configuration and run :lsp-stop. Open a saved file with a matching extension, place the document cursor on a symbol or documented property, and run :hover. Try :definition on a symbol whose source exists locally, then :lsp-back. Use :lsp-status to check configuration and active sessions. Installing a package alone does not verify that it can analyze your project.

Rust · rust-analyzer

Install a Rust toolchain with rustup, then add the server and standard-library sources. Check the installed server:

rustup component add rust-analyzer rust-src
rust-analyzer --version
[[servers]]
name = "rust"
command = "rust-analyzer"
args = []
extensions = ["rs"]
language_id = "rust"
root_markers = ["Cargo.toml", ".git"]

[servers.initialization_options]
cachePriming = { enable = false }
checkOnSave = false

Open an .rs file inside a Cargo project. This is the server entry included in the extracted defaults; edit that entry instead of adding a duplicate. The example disables cache warming and checks on save to reduce background work.

rust-analyzer installation.

C and C++ · clangd

Install clangd using the upstream instructions: LLVM packages on Windows, Homebrew LLVM on macOS, or your Linux package manager. Use the installed clangd executable path if it is not on PATH. Check:

clangd --version
[[servers]]
name = "clangd-c"
command = "clangd"
args = ["--background-index=false"]
extensions = ["c", "h"]
language_id = "c"
root_markers = ["compile_commands.json", "CMakeLists.txt", ".git"]
[[servers]]
name = "clangd-cpp"
command = "clangd"
args = ["--background-index=false"]
extensions = ["cc", "cpp", "cxx", "c++", "hh", "hpp", "hxx", "h++"]
language_id = "cpp"
root_markers = ["compile_commands.json", "CMakeLists.txt", ".git"]

Provide compile_commands.json with your build flags; CMake projects can generate it with -DCMAKE_EXPORT_COMPILE_COMMANDS=ON. Follow the upstream project setup instructions for locating the database. The examples treat .h as C; move it to the C++ entry for C++ headers. Disabling background indexing reduces background work but can limit navigation across unopened files.

clangd installation and project setup.

C# · csharp-ls

Install .NET 10 SDK or newer for the current server, then install the global tool. The project itself may target an older framework.

dotnet tool install --global csharp-ls
csharp-ls --version
[[servers]]
name = "csharp"
command = "csharp-ls"
args = []
extensions = ["cs", "csx"]
language_id = "csharp"
root_markers = ["global.json", "Directory.Build.props", ".git"]

Restore the project dependencies with dotnet restore. For a non-Git project, add your exact solution or project filename to root_markers, such as MyApp.sln or MyApp.csproj. With multiple solutions, use args = ["--solution", "/absolute/path/MyApp.sln"]. Standalone .csx scripts depend on the server’s project support. Keep metadata URI mode disabled; Pötyi opens local files only.

Python · python-lsp-server

Activate your project’s Python environment, install the server there, and check it:

python -m pip install python-lsp-server
pylsp --help
[[servers]]
name = "python"
command = "pylsp"
args = []
extensions = ["py", "pyw", "pyi"]
language_id = "python"

Install your project dependencies in the same environment. Launch Pötyi from that activated terminal, or set command to the environment’s absolute bin/pylsp path (Windows: Scripts/pylsp.exe). The base package uses Jedi for hover and definitions; the optional linting extras are unnecessary for these two features.

Java · Eclipse JDT Language Server

Install Java 21 or newer and Python 3.9 or newer for the launcher. Download and extract a JDT LS milestone distribution from the upstream instructions. Check java -version, then run the extracted bin/jdtls --help launcher. Set JAVA_HOME to the JDK before starting Pötyi.

[[servers]]
name = "java"
command = "/absolute/path/jdtls/bin/jdtls"
args = ["-configuration", "/absolute/path/cache/jdtls/config", "-data", "/absolute/path/cache/jdtls/my-project"]
extensions = ["java"]
language_id = "java"
root_markers = ["pom.xml", "build.gradle", "build.gradle.kts", ".git"]

Replace every absolute path. Use a different -data directory for each Java project; never share it between concurrent sessions. For multiple projects, launch Pötyi from each project with its own config/lsp.toml. On Windows, use command = "python" and put the absolute bin/jdtls script path first in args. Maven/Gradle dependencies must resolve. Definitions inside JARs may use virtual documents that Pötyi cannot open.

Shell · Bash Language Server

Install Node.js 20 or newer with npm, then install and check the server:

npm install -g bash-language-server
bash-language-server --help
[[servers]]
name = "bash"
command = "bash-language-server"
args = ["start"]
extensions = ["sh", "bash", "bats"]
language_id = "shellscript"

Try hover on a documented function or go-to-definition on a shell function call. ShellCheck and shfmt are optional upstream integrations; Pötyi does not expose LSP diagnostics or formatting. This recipe targets Bash and compatible shell syntax. Highlighting .zsh and .ksh does not guarantee this Bash server understands those dialects. Extensionless scripts currently cannot select an LSP entry.

Hover is driven by schema descriptions. Associate your file with a schema by adding a comment such as # yaml-language-server: $schema=./schema.json at its top, pointing to your actual schema. Relative paths resolve from the YAML file. A plain YAML key without a schema description may return no hover text.

Vue: integration status

Pötyi highlights .vue files, but the current Vue language server uses custom tsserver/request and tsserver/response messages to communicate with its TypeScript plugin. Pötyi does not implement that bridge yet, so there is no verified Vue recipe for this client. Do not add .vue to the plain JavaScript entry and expect Vue type information. Ordinary .js, .jsx, .ts, and .tsx files can use the recipes above. See the Vue language server integration instructions.

Using the commands

CommandWhat it does
:rename new_namePreviews a project-wide symbol rename; select Apply changes to commit.
:hoverShows documentation or type information at the document cursor.
:definitionJumps to the first definition returned by the server.
:lsp-backReturns to the previous definition-jump location.
:lsp-statusShows configuration and the number of background sessions.
:lsp-stopCancels pending work and stops all language-server sessions.

The commands work in conventional and Vim modes. Existing shortcuts are unchanged. Hover information appears as plain text in the command bar; use ↑ / ↓ to scroll and Escape to dismiss it. Markdown returned by a server is shown literally.

How it works

Starts when you ask

A server starts on your first :hover, :definition, or :rename request. Current unsaved text in matching documents from both panes is synchronized before the request. Later requests use incremental changes when supported, or full-document updates when required. Typing alone does not trigger synchronization.

Preview a rename

Place the cursor on a symbol and run :rename new_name. Click a file or use Up/Down and Enter to inspect replacements, then Enter to return. Select Apply changes to commit; Escape cancels. Normal Undo reverses the rename across files. Keep affected open buffers open while you need this undo history. If an affected file was closed during the rename and you later open it, close it before undoing.

Rename is limited to 64 files, 10,000 edits, 2 MiB per file and 16 MiB total before/after text. Each preview shows up to 40 replacements with long text shortened. Preparation runs in the background; Apply and Undo validate and write the bounded changes on the editor thread. Stale or unsupported edits are rejected. Extraction into a new file is a later milestone. See the text guide for undo and recovery details.

Background work, bounded resources

Server startup, communication, and shutdown run on background threads. An explicit request copies at most 2 MiB per document on the editor thread. Language servers may still index dependencies or run build tools according to their own settings, so they add memory and CPU usage while running.

Pötyi allows at most two sessions, one per configured server and project. A configured .git marker takes precedence; otherwise the nearest root marker is used, falling back to the file’s directory. A session stops when no matching documents remain open.

Your edits stay protected

Definition jumps reuse open buffers and preserve unsaved text, read-only state, and undo history. A new file uses a clean pane. If both panes have unsaved changes, the jump is refused. Returned locations are checked before replacing a pane.

Results are discarded if either document changes, the requesting cursor moves, the file changes, or the command bar is dismissed or edited. Rename applies only reviewed text edits. Open buffers remain unsaved; Apply writes unopened files identified in the preview. Server-requested commands remain disabled.

After editing the server settings, run :lsp-stop; the next request starts a fresh session. To disable LSP, also set enabled = false.

Troubleshooting

“LSP is disabled” or no matching server

Check that you edited config/lsp.toml under the editor’s working directory and saved it. Put enabled = true before all server entries. Confirm that the document’s extension appears in a server’s extensions list. Run :lsp-status to check the selected configuration.

The server cannot start

Run the configured executable from a terminal. If it cannot be found, install it or use an absolute path in command. Apps launched from a desktop shortcut can have a different PATH from your terminal. Verify that the configured arguments start the server in stdio LSP mode.

No hover information or definition

Place the document cursor on a symbol, rather than whitespace, and try again. Confirm that the server supports the requested feature and can load your project’s dependencies and build configuration. Large projects can take time to analyze. Generated or decompiled definitions are not supported in this version.

The server times out or keeps waiting

Initialization has a 30-second limit and feature requests have a 15-second limit. Run :lsp-stop to interrupt pending work, then retry. Pötyi attempts a brief shutdown before terminating an unresponsive server.

The command disappears or a jump is refused

Moving the cursor, editing, switching files, or dismissing the command bar can make a pending result outdated. Run the command again at the intended location. If both panes have unsaved edits and a definition needs another file, save one pane first.

The document is not supported

Save the file before requesting LSP help. Open documents must contain valid UTF-8 and be no larger than 2 MiB. Files outside these limits remain editable with Pötyi’s existing features. If the LSP commands themselves are unknown, your editor build predates LSP support.

Current limits

This version provides hover, definition navigation, return navigation, and symbol rename. It does not yet display diagnostics, completion menus, signature help, references, code actions, or semantic highlighting. Dynamic capability registration, project file watchers, and virtual documents are also not implemented.

For implementation details and test coverage, see the text guide. The automated checks cover protocol framing, Unicode, incremental updates, unsaved buffers, navigation safety, timeouts, cancellation, and server crashes.

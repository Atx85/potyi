Features

What you can do in Pötyi, grouped by task.

This describes the current source as of 15 September 2026. Downloads may not include every feature yet.

Files & folders

  • Create, open and save files, or save under a new name.
  • Drag files onto the window, or open a folder with potyi ..
  • Open a file at a specific line and column.
  • Recover unsaved text after a crash with :recover.
Details & limits

The terminal’s view command opens a read-only view. Crash recovery restores text into a separate copy, through the last complete saved journal record. It does not restore undo history or the window layout.

Recovery guide

Editing & shortcuts

  • Unicode text editing, mouse and keyboard selection, and system clipboard support.
  • Undo and redo, including grouped typing and bulk changes.
  • Select matching occurrences and edit with multiple cursors.
  • Conventional shortcuts, Vim-style modes, or Emacs-style bindings.
Keyboard modes & limits

Vim mode includes Normal, Insert and Visual modes, motions, operators, counts and dot repeat. Emacs bindings include movement, marks, kill/yank history, search and file/pane prefixes.

Both are subsets of those editors, without their extension languages or macro systems. Occurrence-based multiple cursors are available in conventional mode.

Search & navigation

  • Preview matches while typing, then move forward or backward.
  • Search for literal text or regular expressions, with case controls.
  • Replace one match or every match, with undo.
  • Jump to a line or column, including relative line numbers.
Searching across files

Built-in search works in the current document. For project searches, run an installed tool such as grep or ripgrep in the command terminal, then click a result to open its location.

Layout & settings

  • Two side-by-side editing panes, each with its own cursor and undo history.
  • A command bar with suggestions and Tab completion.
  • Syntax highlighting and adjustable font size and line numbers.
  • Editable settings, shortcut bindings and syntax definitions.
Languages & customization

18 bundled syntax definitions cover C, C++, C#, Python, PHP, Rust, JavaScript, TypeScript, Go, Java, shell, Lua, JSON, TOML, YAML, HTML, CSS and SQL, plus related extensions such as JSX, TSX and Luau.

Defaults are built in; :extract-config creates editable configuration files. The browser syntax designer lets you preview and export highlighting rules.

Highlighting is line-based. The layout is a fixed vertical split; there are no document tabs or persistent graphical project tree.

Terminal & Git

  • Run commands, pipelines and redirects with streaming output.
  • Start directly from the command bar: :term ls.
  • Browse files in columns, complete filenames, and click output locations.
  • Browse Git logs and click commits to read their diffs.
Command controls & limits

Built-in commands include ls, cd, pwd and touch. Recall command history, select and copy output, stop a running command, rerun it or clear the output.

This terminal runs non-interactive commands. Full-screen terminal apps and interactive debuggers are not supported. Git and other external tools must be installed separately; retained output is capped at 8 MB.

Language tools Optional setup

  • Member completion, hover documentation and go-to-definition.
  • Preview project-wide symbol renames before applying them.
  • Review server-provided quick fixes and refactorings.
  • Install a supported server with :lsp install; check setup with :lsp doctor.

Requires a language server and its prerequisites. Available actions depend on the server and project.

Coverage & limits

Installation recipes cover 15 server packages and 22 language profiles. Start, stop, restart and inspect servers from the command bar. Unity setup recognizes generated .sln and .slnx solutions; real Unity projects still need broader testing.

LSP is disabled by default. Requests support saved UTF-8 documents up to 2 MiB. Completion is triggered by member-access operators; general completion while typing and a Problems panel are not implemented.

Language-server guide · Installation help

Formatting

  • :format chooses an installed formatter or supported built-in indentation.
  • Indent supported C-style code, JSON and untitled code without an extra tool.
  • See available providers with :formatters, or choose one explicitly.
  • Undo a formatting change in one step; saving is separate.
Providers & limits

Bundled presets cover rustfmt, Ruff, gofmt, clang-format, shfmt, StyLua, Taplo and Biome. External formatters require manual installation, and custom providers can be configured.

Built-in formatting adjusts indentation with limited syntax support. It is not a full language formatter. Unsupported file types, including Python, need an external formatter.

Formatting guide

Platforms & storage

  • Desktop builds for Windows, Linux, and macOS on Intel and Apple Silicon.
  • File-backed editing and undo, without a full in-memory copy on opening.
  • Lazy line loading and limited caches.
  • An event-driven interface that waits when idle.
Resource use & limits

Edit history and piece metadata still grow with work. Language servers and external commands use their own resources. Large-file editing has different limits from formatting and LSP; not every operation has constant memory use or latency.
